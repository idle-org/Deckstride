# Deckstride 0.1.81 preview

This preview makes multi-Presenter layouts clearer and improves Windows desktop
integration.

- **Presenter and Slides.** The two screen roles now use these names throughout
  the interface and guide.
- **Edit any Presenter layout.** Open Layout on any Presenter and use **Edit layout
  for** to customize another connected Presenter screen. Live edits and both save
  actions remain scoped to the selected screen, including per-project layouts.
- **Default PDF application.** Windows Preferences now shows a visible **Set as
  default PDF app…** button. It registers the portable executable, open command and
  embedded PDF icon for the current user, then opens Default Apps for Windows'
  required confirmation.
- **More reliable initial keyboard focus on Windows.** Presenter activation is
  retried for a short bounded period while fullscreen Slides windows finish mapping.
  A Win32 input-queue fallback aims to make Left/Right work immediately without a
  preliminary mouse click. The sequence ends after startup and does not keep
  stealing focus.

## Windows testing

Extract the Windows x86_64 portable ZIP and run **deckstride.exe**. Confirm that
the Presenter accepts Left/Right immediately after launch, including with two or
more fullscreen displays. Repeat from Explorer, a PDF file association and a pinned
shortcut. Open All slides during startup and confirm that it retains focus.

In Preferences, choose **Set as default PDF app…**, select Deckstride for `.pdf`
in Windows Default Apps, then verify that Explorer uses the Deckstride icon and
double-clicking a PDF opens it. Registration is per user and requires no
administrator rights. Keep the portable folder in a permanent location.

With two Presenter screens, edit each from the other's Layout window. Save one as a
project layout and the other as an all-project layout, restart, and confirm their
visual settings remain independent.

## Validation and packages

Formatting, warnings-denied host and Windows-target Clippy, the complete Rust test
suite and all Python packaging tests pass. Headless whole-application line coverage
for 0.1.79 was **68.66%**, above its 60% CI floor.

Linux x86_64 and Windows x86_64 standalone executables, portable bundles, Cargo
binstall archives and SHA-256 checksums are provided. macOS is not packaged.
Windows foreground activation, file association, physical multiscreen,
clean-machine, sleep and performance behavior remain acceptance checks; this is a
preview for testing.
