# Deckstride 0.1.101

This release adds installable language and theme packs while keeping Deckstride's
fast, portable presentation workflow intact. Packs are ordinary data-only ZIP files:
they work offline, are validated before installation, and appear in Preferences as
soon as they are imported.

## Highlights since 0.1.96

- Import language packs and theme packs from **Preferences → General → Appearance**.
  Installed choices persist globally and load without network access.
- Use the included documented example packs as templates for a new translation or
  visual theme. Pack sizes, paths, identifiers, revisions and expanded contents are
  bounded and validated before Deckstride accepts them.
- Reorganize Preferences into clearer General, Presentation, Performance and Storage
  sections, while keeping the presentation controls that need quick access in the
  main menu.
- Keep the Preferences window stable instead of resizing as the pointer moves.

Deckstride continues to provide independent Presenter and Slides windows, flexible
multi-monitor routing and mirroring, per-screen layouts, buffered PDF rendering,
notes, zoom, pointer and drawing tools, automatic playback, and display recovery.

## Downloads

Portable packages and cargo-binstall archives are provided for:

- Linux x86_64 GNU
- Linux ARM64 musl
- Windows x86_64 GNU
- Apple Silicon macOS 13+
- Intel macOS 13+

Windows and macOS packages are unsigned. On macOS, extract the archive and run:

```sh
xattr -dr com.apple.quarantine /path/to/deckstride
chmod +x /path/to/deckstride
```

Rehearse Deckstride on the actual presentation computer, adapters and display
arrangement before a live event.

## Validation

Linux formatting, warnings-denied Clippy and rustdoc, the Rust workspace tests,
native GUI smoke and Python helper tests pass. The coverage runner completed its
tests but could not satisfy the configured whole-application floor because LLVM
profiles from intentionally terminated worker processes are incomplete. All five
release targets are built and packaged from the tagged commit. Windows multi-screen
behavior has been extensively tested in earlier releases; native runtime testing of
each newly built archive remains appropriate before use in a live show.
